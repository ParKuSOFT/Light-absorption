# 👨‍💻 Задание для разработчика Core (Ветка `feature/core`)

**Проект:** Light-absorption (Виртуальный физический эксперимент)
**Зона ответственности:** Математическая модель, физика процесса, хранение состояния и сохранение данных. 
**Правило:** Не трогаем интерфейс (XAML/UI), работаем только с логикой.

> ⚠️ **Важно:** Делайте коммиты после каждого шага (с осмысленными сообщениями). В конце запушьте ветку и откройте Pull Request в `main`.

---

### 🛠 Шаг 1. Создание структуры проекта
1. Переключитесь на ветку `feature/core`.
2. Создайте библиотеку классов (Class Library) и назовите её **`Light-absorption.Core`** (для логики).
3. Создайте проект тестов **`Light-absorption.Tests`** (используйте фреймворк xUnit или NUnit).
4. Внутри проекта `Light-absorption.Core` создайте три папки: `Models`, `Solvers` и `Export`.

---

### 📦 Шаг 2. Реализация паттерна State и физической модели
*Согласно лекции 12 (Задача Коши и формат State).*

1. **Класс `ExperimentState`:**
   * Создайте класс в папке `Models`.
   * Он должен содержать массив `double[]` (значения R, G, B) и свойство `StateSize`.
   * Реализуйте метод `Clone()` для глубокого копирования массива (это нужно, чтобы Solver мог сохранять историю точек, не перезаписывая старые).
2. **Класс `BeerLambertModel`:**
   * Создайте класс в папке `Models`.
   * Определите физические константы из лабораторной работы:
     * \(\alpha_R = 0.8\)
     * \(\alpha_G = 0.3\)
     * \(\alpha_B = 0.1\)
   * Напишите метод расчета интенсивности по формуле: \(I = \exp(-\alpha \cdot z)\).

---

### 🧮 Шаг 3. Реализация задачи Коши и Solver
*Согласно лекции 4 (Этапы разработки модели).*

1. **Интерфейс `ISolver`:** Создайте интерфейс в папке `Solvers` с методом `Solve(...)`.
2. **Класс `EulerSolver`:** 
   * Создайте класс в папке `Solvers`, реализующий `ISolver`.
   * Метод должен принимать начальное состояние `state_0` (где \(R=G=B=1\)) и шаг `dz`, а затем считать значения на заданном отрезке (до максимальной глубины).
   * *Примечание:* Если в модели нет зависимости от времени \(t\), а есть только зависимость от глубины \(z\), вы можете реализовать простой цикл, который шаг за шагом (или аналитически) считает точки для графика, либо адаптировать его под дифференциальное уравнение \(dI/dz = -\alpha \cdot I\).

---

### 💾 Шаг 4. Экспорт данных
1. В папке `Export` создайте класс `CsvExporter`.
2. Напишите метод, который принимает список состояний (историю вычислений) и сохраняет их в CSV-файл. 
3. Формат сохраняемых данных: `z, R, G, B`.

---

### 🧪 Шаг 5. Написание Unit-тестов
В проекте `Light-absorption.Tests` напишите тесты, проверяющие граничные условия из лабораторной работы:
* **Условие 1:** При \(z=0\), значения \(R=G=B=1\) (белый вход).
* **Условие 2:** При \(z \to \infty\), значения \(R, G, B \to 0\) (полное поглощение).
* **Условие 3:** При \(z > 0\) должно выполняться неравенство \(R(z) < G(z) < B(z)\) (так как красный гаснет быстрее).
* **Условие 4:** Проверить, что `ExperimentState.Clone()` действительно создает независимую копию массива (изменение клона не меняет оригинал).

---

### 🚀 Финализация
1. Убедитесь, что все тесты проходят (зеленые).
2. Сделайте `git push origin feature/core`.
3. Откройте Pull Request в ветку `main`.
